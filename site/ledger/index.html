    How it works

    The padlock is the tell.

    Browsers only trust a certificate if it has been written to public Certificate Transparency logs. Phishers can't skip that step, so every lookalike with a padlock shows up there first.

    Issued

    Someone gets a certificate for a domain from Let's Encrypt, Google, Sectigo or any public CA.

    Logged

    The CA must write it into public, append-only logs (Merkle trees) before browsers will trust it.

    Read

    Ledger tails the busiest logs as they grow, usually within a minute of each entry being written.

    Judged

    Every hostname is checked for homoglyphs, digit swaps, typos and your name inside someone else's domain.

    Acted on

    You get an alert with the reasons, the certificate record and a takedown request written for you.
